# Revisar la entrega

**Solo informa y propone. No cambies nada por tu cuenta.**

## 1. Validar la spec

Recorre la spec activa RF por RF y arma una tabla: requisito, prueba que lo cubre, resultado (ejecuta las pruebas) y estado. Veredicto: ¿spec cumplida?

## 2. Revisar el repositorio

Con el MCP de GitHub y los archivos:

- Issues abiertos y en qué columna del tablero están.
- PRs abiertos sin revisión.
- Si cada integrante tiene al menos un PR fusionado.
- README sin [corchetes] por completar, con pasos para ejecutarlo y el enlace a la demo.
- Sin secretos ni datos personales reales.
- La demo desplegada abre y funciona.

## 3. Revisar el pitch

`docs/pitch.md` completo: problema, propuesta de valor, demo en 3 pasos y quién presenta qué.

## 4. Informe

Una tabla corta con **Listo**, **Falta** y **Riesgo**, y las 3 cosas más urgentes en orden. No digas quién debe hacerlas: eso lo reparte el equipo.

Si falta tiempo, recomienda **recortar alcance** (moviendo requisitos a "Fuera de alcance" en la spec, por PR) antes que entregar algo roto.
